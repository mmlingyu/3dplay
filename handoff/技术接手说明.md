# 《圆圆的河谷》技术接手说明

核对日期：2026-10-14。对象：继续开发的同事及其 AI。本文以交接时的 `src/`、`package.json`、锁文件、测试代码及现有检查记录为依据。历史方案描述的是设计意图；判断某功能有没有实现，应以代码和实际运行结果为准。

这是一个 Vite + Three.js 的浏览器游戏，使用原生 JavaScript ES modules、HTML 和 CSS，没有 React、后端数据库、账号系统或模型 API。三维人物、场景、纹理与 SVG 图标由项目代码构造；界面中的“AI 建筑点子卡”是预先制作的建议，没有实时 AI 调用。制砖说明中的来源链接可打开外部网页，但游戏主流程不依赖这些网页。

## 1. 先在自己的电脑运行

在含 `package.json` 的项目根目录执行，保留交接包里的 `package-lock.json`：

```sh
node --version
npm ci
npm run dev
```

打开终端实际显示的网址。`npm ci` 按锁文件安装交接版本；`npm install` 适合明确要变更依赖时使用。安装依赖需要网络，已经构建的游戏运行不需要模型密钥。

目前锁定 Three.js `0.186.1`、Vite `8.3.4`、Playwright `1.62.1`。锁文件中 Vite 的 Node 要求是 `^20.19.0 || >=22.12.0`，Playwright 要求 `>=20`。因此 Node 20.19.x 及之后的 20.x，或 Node 22.12.0 及以上满足这组声明；Node 21 和 Node 22.0—22.11 不满足。为与 README 一致，可选满足条件的 Node 22.12 或以上版本。这是依赖声明的支持范围，不等于所有 Node 版本都已逐一实测。`package.json` 当前没有另写 `engines` 字段。

检查与正式预览：

```sh
npm test
npm run build
npm run preview -- --port 5174
```

`build` 生成 `dist/`，`preview` 用 HTTP 提供构建产物。不要直接双击 `dist/index.html` 当作运行方式。开发和预览都配置了 `--host 0.0.0.0`，平板可以尝试访问电脑的局域网 IP 和实际端口，但电脑必须保持服务运行、设备之间能互访。README 中原开发者电脑的 IP 不是同事电脑的固定地址。当前未发布公网；`dist/` 可在另行决定部署后交给静态托管服务，Vite 的 preview 是检查工具。

浏览器流程检查需另一个终端，并保持上面的预览进程运行：

```sh
npx playwright install chromium
npm run test:browser
# 如果测试地址不同：
GAME_TEST_URL=http://127.0.0.1:5175 npm run test:browser
```

安装 Chromium 会下载浏览器。上述环境变量写法适用于 macOS/Linux shell；Windows 可在 PowerShell 先设置 `$env:GAME_TEST_URL`，再运行测试。不需要为此改变现有 VPN、代理、DNS 或网络出口；网络故障先做只读诊断。

## 2. 入口和模块边界

| 文件 | 真实职责与主要入口 | 修改时应注意 |
| --- | --- | --- |
| `index.html` | 主页面、画布、摇杆、动作按钮、欢迎页；末尾加载 `/src/main.js` | 页面 ID 被主程序直接引用，改名要同步调用方 |
| `src/main.js` | 创建 `GameState`、`RiverWorld`、面板；键盘/摇杆、交互、建造、保存角色位置、每帧计时 | `interact()` 分派采集/面板/实验；`build()` 发起放置；`frame()` 决定什么时间推进 |
| `src/game-data.js` | `ITEMS`、`RECIPES`、原料名单、园地坐标、地形、建造保护区、存档 key | 材料 ID、园地 ID/坐标、地形变化可能影响旧存档 |
| `src/game-state.js` | 不依赖 DOM/Three 的规则与存档；导出 `GameState`、`createInitialState()` | 库存、放置、撤回、合成、窑炉、种植、补给和箱子规则集中在此 |
| `src/world.js` | 导出 `RiverWorld`；创建模型、渲染、点击拾取、运动、碰撞和木球简化物理 | `sync(state)` 将状态反映到场景；`update(dt,input,paused)` 推进运动；不会替代库存规则 |
| `src/panels.js` | 导出 `createPanels(...)`；背包、合成、窑炉、菜园、补给、箱子、帮助、暂停与导入导出 | 返回 `open/close/isOpen/refresh`；按钮调用 GameState，面板自身还保有临时题目与格子选择 |
| `src/style.css` / `src/icons.js` | 页面布局、响应式样式、`icon(name,size)` 的 SVG 图标 | 改图标名须核对真正存在的键；改布局要查看触屏尺寸 |
| `test/game-state.test.js` | Node 内置测试验证状态规则 | 与三维显示、触屏和儿童真实体验是不同层面的验证 |
| `test/browser-check.js` | Playwright 桌面 Chromium 流程；写入 `output/browser-verification.json` | 使用独立浏览器上下文，不清理正常使用者的存档 |

正常链路是：点击或键盘 → `main.js` / 面板 → `GameState` 变更规则状态 → `subscribe()` → `world.sync()` 和界面刷新。角色的连续移动位置在 `RiverWorld` 中，主程序通过 `storePlayer()` 写回 `state.player`。新增库存动作优先走状态 API；直接改 `game.state` 不会自动校验、通知或保存。

`window.__valley` 暴露 `game/world/panels` 与几项操作，供浏览器检查和本机调试使用。这不是稳定的外部 SDK，也不是儿童需要接触的功能。

## 3. GameState 可用接口

多数动作返回 `{ok, message, ...}`；成功和失败都应让界面展示 `message`。`placementProblem()` 返回错误文字或 `null`，`getMatches()` 返回配方数组，`subscribe()` 返回取消订阅函数。

| 用途 | 当前方法 |
| --- | --- |
| 生命周期 | `new GameState(storage?)`、`subscribe(listener)`、`mutate(fn)` |
| 库存与原料 | `addItem(item,count)`、`consumeItem(item,count)`、`harvest(item)` |
| 搭建 | `placementProblem(item,position)`、`placeBlock(item,position)`、`removeBlock(id)`、`undo()` |
| 格子合成 | `getMatches(grid)`、`craft(grid,recipeId?)` |
| 可选补给 | `rewardOrder(id,{item,count},correct=true)` |
| 箱子 | `depositChest(id,item,count=1)`、`withdrawChest(id,item,count=1)` |
| 制砖 | `startKiln(count=2,mode='normal')`、`getKilnStatus()`、`claimKiln()` |
| 园地 | `plant(plotId)`、`water(plotId)`、`transplant(fromId,toId)`、`harvestPlant(plotId)` |
| 时间 | `tick(seconds)`，`update(seconds)` 是它的同义入口；两者单位都是秒 |
| 存档 | `save()`、`load()`、`exportSave()` 返回 JSON 字符串、`importSave(text)` 校验后替换世界 |

`GameState` **没有 `hasWorkbench()` 方法**。面板里的 `game.hasWorkbench?.()` 是可选调用，当前主要靠上下文和 `state.blocks` 判断工作台，不要照着这一行虚构已有 API。

合成格子用矩形二维数组，空格是 `null`，材料用 `ITEMS` 中的 ID。匹配会去掉外圈空行/空列，因此允许同一图案平移；不会自动旋转图案或把横排当作竖排。四木板方形同时匹配工作台和木球，确认时必须选 `recipeId`。摆格子只记录面板临时选择，确认合成才消耗库存。

公共工作台免费开放 3×3，不必先做一张自己的桌子。自制工作台仅在背包里时不解锁大格子，需放进世界；当前只要世界里存在已放置工作台，随身工坊也允许切到 3×3，不要求一直站在自制桌旁。打开公共桌或自己已放的桌，面板直接以 3×3 打开。大格子使用条件目前由面板控制，`GameState.craft()` 本身只检查图案与库存，不再检查玩家距离或解锁状态。

## 4. 当前世界的运行规则

地图是固定 32×32 河谷，不是无限生成世界。建造整数坐标 `x/z` 范围为 `-16..15`，方块的 `y` 是底面高度，上限为 `12`；溪床 `x=3..5` 的地形高度为 `-1`，其余为 `0`。桥、示范坡道等额外表面由 `RiverWorld.surfaceAt()` 处理。

采集采用固定取材点补给模式：木料、石块、制砖黏土、树枝、种植土、清水、种子均能反复采集，每次 2 份。`main.js` 给同一取材点加了 1.5 秒间隔。这不是砍掉一棵树、挖空地块后再长回来的资源模拟；树木多数是场景装饰，地图资源点不会耗尽。砖和豆子分别通过加工和种植获得。

放置要求空格、足够库存、界内，且接地或与已放方块面邻接。公共设施、菜地、通道、小屋和示范球道有建造保护区。这里只在放置时检查连接；取走支撑不会触发整体倒塌，也没有重量、跨度、强度或真实房屋安全计算。`isProtectedCell()` 是建造限制，人物碰撞由 `world.js` 单独处理，不能把二者当同一个系统。

木球是简化重力、坡度与碰撞模型，不是完整物理引擎。目前同时最多 4 个活动球，约 13 秒后回收显示对象；球的活动状态不存档。示范坡道可直接放球；自建球道模式只要求背包中有木球，不会每放一次消耗一个球。这是可复用玩具的当前实现。

正常制砖消耗 `count` 份黏土和 1 份树枝，默认 2 份；API 允许 1—10 份，面板固定为 2 份。四个阶段各约 6 秒：`moistening → drying → firing → cooling`，到 24 秒才 `ready`，领取后得到砖并回到 `idle`。`wet` 和 `fastCooling` 用免费工坊试样，不耗普通原料，演示结果为 `failed` 并给碎片。确定的游戏演示结果不能表述成“现实只要这样就必然开裂”。格子合成不直接把黏土变成砖。

菜园固定 6 格。水分 `0` 是干、`1/2` 适宜、`3` 积水；仅适宜条件累计生长，`age=90` 成熟。适宜条件下每 60 秒水分降一级；排水好的格子积水 8 秒后回到 `2`，排水差的格子保持积水，可移栽。成熟后不再继续干燥或受积水阻碍，采收只检查成熟，得到 2 份豆子和 1 份种子。固定适宜光照，没有季节、营养、虫害、植物死亡及完整移栽风险模型，不能宣称真实全套生态。

所有格子数量、产量、建筑连接和时间快进都是游戏约定；现实材料说明集中在物品说明、帮助与加工面板的折叠说明里。改规则时须同时改解释，避免界面把简化说成现实物理事实。

## 5. 暂停、面板与可选奖励

`main.js` 的 `frame()` 将运动步长限制到最多 0.05 秒，状态时间则使用当前可见帧经过的时间，单帧最多计 2 秒。`GameState.tick()` 累计小数时间，按整秒推进并保存。长时间卡顿时可能少计部分现实经过时间；不是精确后台时钟。

尚未点“开始”、页面隐藏或暂停菜单打开时不推进加工与生长。其他面板打开会停角色与木球运动，但加工/植物继续，因此看窑炉不会把制砖停住。失去窗口焦点的 `blur` 事件只清理输入并保存；如果页面仍可见，仅凭失焦不保证加工停止。当前没有内置固定时长、强制休息或延长游玩奖励，家长计时、孩子可以随时停下。

补给只提供地图本来就能采到的原料，答错不扣材料、没有次数失败处罚，也不控制探索、工具或时长。当前每份正确补给 2 份原料。这是待真实试玩调整的初始参数，不是已经验证的学习效果。

防重复要分两层看：`rewardOrder()` 把已领取的 **同一个 ID** 记入 `claimedOrders`，重载存档后仍拒绝同 ID。面板却在每次 `createPanels()` 时生成 3 个带随机 ID 的订单，题目和 `answered` 状态没有保存。关闭再打开面板不会换一批；刷新页面会生成新一批，仍可领取原料。不能把“同 ID 防重领”描述成“刷新也没有新补给”。是否把题目持久化，需由产品目标决定，不能顺手引入每日签到或答题门槛。

## 6. 存档结构与升级注意事项

当前 `version=1`。存档 key：

```text
正常世界：yuanyuan-river-valley-v1
损坏原文备份：yuanyuan-river-valley-v1-damaged-backup
```

数据存在当前浏览器、当前网站来源的 `localStorage`。协议、主机或端口不同就是不同来源，电脑与平板不自动同步；换网址、清理网站数据或使用临时窗口会影响恢复。通过 JSON 导出/导入搬运世界。

结构如下，省略号表示完整材料数量表或园地数组，不是可以照抄的 JSON：

```js
{
  version: 1,
  inventory: { wood: 4, plank: 12, /* 所有 ITEMS 的非负整数数量 */ },
  blocks: [{ id: 'block-1', item: 'plank', x: 0, y: 0, z: 0, rotation: 0 }],
  player: { x: -5, y: 0, z: 5 },
  settings: { sound: true },
  stats: { gathered: 0, crafted: 0, built: 0, orders: 0 },
  garden: [{ id: 'plot-1', x: 8.2, z: 5, drainage: 'poor',
    planted: false, age: 0, moisture: 1, harvested: false,
    moistureElapsed: 0, drainElapsed: 0 } /* 共 6 格 */],
  kiln: { stage: 'idle', elapsed: 0, count: 0, mode: 'normal' },
  chests: { /* 已放箱子的 block ID: 完整材料数量表 */ },
  claimedOrders: [],
  nextId: 1
}
```

`rotation` 是 `0..3` 的四分之一圈编号，显示时乘 `Math.PI/2`，不是直接存角度或弧度。`age/elapsed/moistureElapsed/drainElapsed` 单位均为秒。统计值是累计动作量，不等于当前建筑数，也不是学习成绩。

`mutate()` 保存并通知；主程序还约每 4 秒保存一次移动位置，在打开/关闭面板、开始、失焦、页面隐藏或退出时尝试保存。没有存档时间戳用于离线推进。重载会清空撤回历史和不足 1 秒的内部计时余量；撤回历史不是存档的一部分。

`load()` / `importSave()` 使用文件内部的 `validateSave()` 校验版本、材料、位置、箱子对应关系、园地与窑炉阶段等。非法导入不替换当前状态；**当前没有跨版本迁移函数**。损坏本地原文必须先写到备份 key 并读回确认，才允许后续保存覆盖主 key；备份失败就保留原文并提示导出。备份 key 只有一个，是损坏原文的保留位置，不是完整的滚动版本历史。暂停菜单的“导入前备份”先保留在该页面内存中，可手动下载，尚不是另一个自动持久化的多版本备份库。

保存失败时 `storageError` 提供提示，`save()` 返回 `ok:false`；没有可用存储时也明确刷新/关闭后不能恢复。业务动作仍可能成功改变内存世界。有效导入也可能已经替换内存世界，但随后持久保存失败；`importSave()` 当前仍返回导入成功，应结合 `storageError` / 保存状态提示判断是否需下载备份，不能把导入成功等同于浏览器落盘成功。

升级前先导出真实存档，再在副本和独立浏览器上下文验证。尤其注意：

- 改材料 ID、删除物品或改变 `placeable`，可能使旧库存/旧建筑无法通过校验。
- 改园地数量、ID、坐标、排水类型，当前严格比较会拒绝旧园地数据；改地形高度或建筑范围也可能拒绝旧建筑。
- 改窑炉阶段、24 秒时长或植物 90 秒上限，需同步推进逻辑和校验，不能只改面板文案。
- 当前导入面板限制文件 2 MiB，API 限字符串 5,000,000 字符；建筑最多接受 12,000 个、领取 ID 最多 10,000 个。这些是校验上限，不是性能承诺；长期增长和奖励重生尚需处理。
- 建造保护区在放置时检查，导入校验目前不重新检查 `isProtectedCell()`，也不检查整座建筑是否仍接地。拓展地图或公开导入前需决定旧建筑冲突的迁移办法。
- 做版本升级应明确读取旧 key、转换、校验、备份、写新版本的步骤；不能仅改 `STORAGE_KEY` 后宣称用户进度被迁移。没有用户明确要求，不清理原 key 或已有存档。

尚未验证：孩子本人独立操作、实际 iPad/Android 平板、Safari/WebKit、真实中文语音、低性能设备和长时间发热、很多建筑时的性能与存储、长时间重复游玩、学习效果及生活迁移、任意自建球道的物理正确性、所有导入/存储故障场景。设备不支持 WebGL 时有提示页，没有另一个完整 2D 游戏版本。

## 8. 已知小问题与下一步顺序

1. **先修一个可独立验收的小 UI 问题。** `main.js` 关闭声音时调用 `icon('mute')`，图标库实际有 `sound-off`，因此关闭按钮可能显示默认叶子。声音开关功能仍有效。把名称统一后验证开关图标与中文标签即可，不必重构声音系统。
2. **先做真实设备与儿童观察。** 观察摇杆/视角、动作按钮、选位置再放、合成确认的第一次卡点；优先解决影响自主操作的问题。不能把成人或 AI 觉得可爱作为已验证的孩子偏好。
3. **补自动走路的绕障与失败处理。** `walkTo()` 是朝目标直线趋近，`canMove()` 做碰撞/高度检查，尚无完整寻路或绕障导航。新增墙、树或建筑可能让角色卡住；手动摇杆会取消自动前往。不能宣传“一点必能到达任何地点”。
4. **确定跨次补给与存档增长策略。** 当前刷新重建订单，可再次获得补给；长期 `claimedOrders` 增长会触及校验上限。先选择体验目标，再决定持久题目/清理已无意义 ID/迁移办法，维持全部资源可正常采集和题目可跳过。
5. **按实际障碍补跨浏览器、备份导入、性能检查。** 优先真实平板，再扩建大地图和新生态。把新增断言与具体风险对应，避免只写重复实现细节的测试。

给后续 AI 的最小工作约束：先读本说明、README、项目长期记忆和目标文件；复述这次具体要改的行为；确认哪些是游戏约定；按模块修改；不顺手加入答题门槛、强制时长、实时儿童聊天或云端收集；保存用户原世界并验证旧存档；报告改动、实际检查和未覆盖之处。网络安装出现问题也不构成改变现有 VPN/代理的授权。
