# 给 AI 的接手提示词

更新：2026-10-14。

把项目文件夹交给 Cursor、TRAE、Claude、Codex 或其他能读取文件、运行项目的 AI，再复制下面第一段。工具名仅表示可选工具，不表示已经确认原开发者使用了它们。不能访问文件或浏览器的 AI 应明确说明能力缺口，不能声称已经读过、跑过或试玩过。

## 第一次接手：理解、运行、核查

```text
请接手当前文件夹中的《圆圆的河谷》。这次任务是理解现有项目、运行检查并评审；我尚未要求新增功能或重写游戏。不要让我重新讲述已经存入文件的背景。

先按顺序阅读：
1. AGENTS.md、开始这里.md、README.md。
2. PROJECT_MEMORY.md 顶部的当前状态和接手声明，然后阅读其余记录。
3. handoff/项目上下文.md、handoff/需求决策记录.md、handoff/技术接手说明.md。
4. 开发过程记录.md、handoff/试玩反馈模板.md、handoff/需求原话摘录.md。原话用于核对来由，不把其中观点当作已证实事实或全部当前要求。
5. package.json、锁文件、index.html，src/ 下全部模块，以及 test/ 下的核心与浏览器检查代码。需要核查科学或历史决策时再读对应 research/ 文件和设计文档。

文档有时间顺序：PROJECT_MEMORY 的当前状态与 2026-10-14 接手声明优先于旧的“待审阅、未授权、尚未制作”记录。2026-10-13 已授权并完成首版，不能把历史提案当成当前未决事项。用当前代码确认“已实现什么”，用最新明确决策确认“应该做什么”；若两者矛盾，指出具体文件和差异，不自行改变目标。原会话的个人称呼和主观人物评价不是对接手人的要求，也不能作为评价同事或工具的事实。

保留这些已经明确的边界：
- 对象是用户描述的六岁、一年级孩子；优先兴趣、自主探索、逻辑和物理条件理解、独立解决问题。持续保存的开放世界是主结构，不改为三个独立小游戏。
- 必需原料都能正常采集，加工品能正常制作。答题是可选的额外补给，答错不扣材料，不垄断地图或唯一工具。不要故意拖慢采集逼孩子答题。
- 家长管理每次约半小时、最长一小时的时限；这不是医学安全承诺。答题不增加分钟数；支持随时停下、保存、下次继续，不新增固定分段或强制通关后退出。
- 格子配方的排列、数量、产量及建筑连接是游戏约定；连接检查不是现实承重判断。球道、制砖、菜豆生长是有边界的简化与快进模型，角色软萌动作不改变实验物体规则。不得把任意泥土变砖、奖励保证喜欢学习等未证观点写成事实。
- 首版没有儿童实时 AI 聊天。点子卡是预制的游戏建议，不伪装成实时回答，不自动增加账号或付费 API。
- 已有浏览器模拟和测试不等于孩子本人或实体平板试用。具体兴趣、长期复玩、教育效果、真实生活迁移、设备性能和语音可用性仍需观察；不猜学校当前教材，不把不参与某活动解释为能力差或诊断。

然后进行可复核的运行检查：
1. 核对 Node 版本、包管理脚本、依赖与已有进程。依赖齐全时直接使用；缺失时按锁文件安装。先保留已有测试记录，避免把旧证据误当本次结果。
2. 运行 npm test 和 npm run build。启动与本次构建匹配的本地预览，使用终端实际显示的地址；不假定历史 IP 或端口仍有效，也不停止无关进程。
3. 按 handoff/技术接手说明.md 运行 npm run test:browser；地址不同时通过 GAME_TEST_URL 指定。使用独立测试浏览器上下文，不清理实际使用者的存档。缺少 Chromium 时如实记录，安装或下载失败时不要声称通过。
4. 有浏览器工具时实际走一遍采集、试摆合成、选产物、确认、搭建和撤销、窑炉、菜园、可选补给、暂停及存档；检查 1024×768 平板布局，必要时兼看 390×844 窄屏。验证触控、正文滑动、确认按钮可见、声音关闭反馈及退出恢复。区分真实交互和直接调用测试接口，说明哪些只做了模拟。

允许产生必要的依赖、构建产物和本次测试记录；本轮不修改 src、需求文档、锁文件或正常使用者存档。发现问题先记录证据和最小修正建议，不顺手重构或添加功能。

不要调整当前机器的 VPN、代理、节点、地区、线路、模式、TUN、分流、订阅或配置；也不要通过更换 Wi-Fi、DNS、系统代理、路由改变网络出口。网络错误先做只读诊断。涉及改变出口时必须取得操作者对该次具体变更及影响范围的明确批准；普通“继续、想办法、自主推进”不是批准。本限制同样适用于子代理和脚本。

最后给我一份简短接手结果：当前目标与已实现闭环；实际执行的检查及结果；证据明确的问题（最多三个、附路径或截图）；仍需真实试玩的问题；你建议下一步先解决的一件事及理由。区分用户已确认、公开证据、代码现状、设计假设，不将成人偏好或奖励领取次数当作教育效果。只问文件中不存在且确实影响下一步的问题。
```

## 发现界面问题后：以证据修一件事

替换方括号中的内容，再复制。若暂时只有“看着不够好”，先让 AI 提出可比较的样式，不直接给它“全部美化”。

```text
在完成接手核查后，请解决这一件界面问题：[例如：某平板的工坊确认按钮被遮挡]。复现条件：[设备/浏览器/方向/窗口尺寸/操作路径]；证据：[截图或具体行为]。

先独立复现并判断成因。若只是布局或状态反馈错误，直接做最小修复；若涉及玩法或整体视觉方向，先给两个可比较的办法及各自影响，供我选择。本次不增加学习题、不改变资源与时间规则、不重写三维世界。说明修改解决哪个儿童操作障碍，不以“成人觉得更漂亮”代替理由。

用修改前后的同尺寸截图和真实点击/触控/滚动核验结果；相关按钮至少满足当前项目的触控尺寸约定。运行与改动相关的检查。报告剩余限制，把已确认的设备信息与解决办法记入项目文档，避免下次再问。遵守接手提示中的网络出口与存档保护约束。
```

## 想增加机制时：先比较，再选定

```text
我想考虑：[新机制]；希望改善：[可观察的孩子行为]。这次先评审，不实施。

请检查它与现有目标及闭环是否一致，不因为是我的想法就认定值得做。给出“保留现状”和两种最小实现的比较：孩子能做什么、学习负担与独立操作成本、可能误教的现实规律、是否挤掉探索/加工、开发与存档成本。指出我的描述里哪些是事实、哪些是假设；新增科学说法先查直接可靠来源。

提出一次小规模试玩能观察的判断标准，以及可以撤回的最小实验。不要承诺奖励会保证兴趣或现实迁移，不增加答题门槛或游玩分钟数。若资料足够就直接形成可审阅结果；只询问真正缺少的信息。待我明确选定实现范围后，再进行代码修改和对应验证。
```

## 收到真实试玩反馈时：拆开行为与解释

```text
以下是按 handoff/试玩反馈模板.md 记录的反馈：[粘贴记录]。请先分析，不修改代码。

区分直接观察、孩子原话、成人提示、成人推测和技术故障。分别判断是否看到奖励领取、知识/条件理解、现实迁移的证据；未观察到的就写未知，不用答对次数推定学习效果。

列出这个问题的两种合理解释及当前证据，选一项最值得下一轮验证的改进，与保留现状比较。保持本轮只改一个变量，给出复测行为和撤回条件。不诊断孩子、不要求补充无法取得的第一视角，不把一次不愿玩当作固定偏好。新的已确认事实写入接手决策记录，假设仍标为假设。待我选择改进后再实施。
```

## 改存档或数据结构时：先保住现有世界

```text
请实现这一项已选定的数据变化：[变更及理由]。先阅读当前存档版本、校验、损坏原文备份、导入确认、暂停与离线时间规则，列出会影响的旧存档字段。

在独立测试环境中准备旧版有效存档、损坏存档和不能本地保存的情况；不用正常使用者数据，不直接删除 localStorage，不静默重置世界。给出最小兼容或迁移办法及失败后的保留/导出路径，然后在当前授权范围内实施。若确实需要改变已有玩法或放弃旧存档兼容，先给我具体取舍，不能自行决定。

用有意义的回归检查验证材料、建筑、箱子内容、植物、加工和角色状态，确认无效导入不覆盖、迁移失败可恢复、暂停与重载不增加离线进度。更新 README、技术说明和相关决策记录；报告兼容范围与尚未覆盖的风险。遵守原机器的网络出口限制。
```
