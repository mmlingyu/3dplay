# 我的河谷

面向六岁孩子的第一版三维建造沙盒。地图与建筑会保留；采集、格子合成、搭建、球道、制砖与豆苗园地都在同一个世界里。

这是可试玩版本，尚未经过孩子本人或实际平板的体验验证。第一轮主要观察她能否独立操作、是否愿意探索，以及能否说出一次改变条件前后的区别。

2026-10-14 完整交接：同事及接手 AI 先读 [开始这里](开始这里.md)，其内链接到上下文、技术说明和可直接复制的 AI 接手提示词。旧讨论与当前实现的差别已在交接文档中说明。

## 本机运行

需要 Node.js 22.12 或更新版本。

```sh
npm ci
npm run dev
```

浏览器打开终端显示的本地地址。正式构建与预览：

```sh
npm run build
npm run preview -- --port 5174
```

预览默认可使用 http://127.0.0.1:5174 ，实际以终端显示的端口为准。同事接手后用自己电脑的终端显示的 Network 地址供同一可互访网络中的平板尝试访问，不要照抄原电脑的 IP。电脑需要保持预览进程运行；IP 可能随网络环境改变。本次仅读取了原电脑的地址，没有修改网络设置。实际平板的访问与运行性能尚待确认。

`dist/` 可以交给普通静态网站托管。运行游戏不需要模型 API、账号、支付、服务器数据库或外部游戏资源下载。当前没有发布到公网。

## 怎么玩

触屏：左下摇杆走路；拖动画面转视角，双指缩放。点地点标签可自动前往并操作。直接点场景中的材料后，可点右边动作按钮采集。

搭建：先点底栏材料。电脑单击场景看预览，双击目标位置直接放置；触屏先点场景出现预览，再按住预览物体拖到目标格，松手自动放置，拖空白处仍转视角。红色预览会说明不能放置的原因。选择和拖动预览不扣材料，放好后需要重新选位置。原“确认放置”按钮保留作为备用。双指缩放、触控取消、在界面上松手或切换材料不会确认旧拖放。旋转、取消和撤销都在底部；没有库存的材料会提示获取方式，不切换模式。“拆除”取回自己的方块；撤销能恢复刚才的搭建或取回操作。箱子里存放的材料会一起返还。

电脑还支持 WASD / 方向键移动、空格跳跃、E 操作、B 合成、I 背包、R 转向、1–6 选择材料、Enter 确认放置。搭建时 Esc 取消搭建，其他时候 Esc 暂停。移动端支持预览拖动松手放置，也可点大按钮，不要求双击或等待长按计时。

放置交互回归：运行开发服务后执行 `node test/placement-check.js`，覆盖电脑、平板横竖屏、手机与窄屏触控；使用独立浏览器上下文，截图输出至系统临时目录。

快捷手势回归：`node test/placement-gestures.js`，覆盖电脑双击只放一份、触屏拖动后松手放置、取消/缩放/非法位置/界面遮挡/切换材料不误放，以及空白拖动仍转视角。

先从一份木料做四块木板开始。四块木板的方形配方可以选择工作台或木球；工作台放好后能使用三乘三格子。公共工作台也始终可用。八块木板围一圈、中间留空，可以做储物箱。其他配方可以自由试摆或查看配方书；确认前不会消耗材料。

工坊按钮、B键和场景工作台默认打开三维木作近景：前方材料托盘 → 桌面实体插槽 → 右侧产物 → 拉木杆。用鼠标/手指把材料拖进槽，也可点材料再点空槽；点已有材料拿回。上方图卡演示摆法，试摆不扣库存。同图案有多个结果时先点右侧物品；木拉杆向下拉过有效行程并松手才制作，短拉不提交。材料不足会提示，制作后产物在展示位出现且加入原背包。

“制作 · 拉杆备用”按钮可用点击/键盘操作，不加二次确认；“二维格子备用”保留原配方书、自由试摆和确认制作。公共或已放置工作台允许大桌面，背包里未放置的桌子不解锁。双指（含第二指落在界面上）、触控取消、隐藏页面、画布外松手或关闭面板取消旧拖放；离开只丢弃试摆，不扣料。拉杆与插槽是游戏制作约定，不是现实切削模拟。

开垦：先用摇杆或方向键走到已开放草地的边界。靠近时会高亮身边未整理草地，并问“前面还没整理，想去看看吗？”；点“开垦这里”开放对应 8×8 区块，点“先不”留在原世界，离开后再走近仍可探索。小地图“开垦探索”仅显示当前位置可整理的草地；在小院里打开只会给走向边界的引导，不能远程开区。角色所在开放区的共享边界距离不超过2.2格才能开垦，不允许隔角或站在未开区开垦；提交时重新检查真实位置。

新区可以行走、搭建和滚球；原 32×32 世界坐标与作品保持，最多新增 48 区块，不需答题、支付或等待。每个新区有一个固定随机发现：小兔与物资包、草地观察与物资包或宝箱。点击发现/标签后走近领取，动物不会被变成材料；奖励来自物资包或箱子。领过后仍可观察，但再点、刷新或导出重载都不会重复发奖。

发现补给包含已有木料、树枝、种植土、清水或加工物体；当前默认种子的宝箱会给木板、工作台或储物箱。配置也支持其他有效种子中的斜坡奖励，但没有种子选择界面。随机结果按存档种子与区块稳定生成，当前新世界使用相同初始种子。没有新增任意高级物品、新材质或完整动物生态；普通采集和加工仍可用。新区自由播种尚未实现，菜园仍为原六格。

所有必需原料都能从地图取材点获得，加工品能正常制作。补给仓库的三道小练习提供额外原料；答错不扣材料，也不会控制探索、工具或游玩时长。补给数量是初始试验参数，不代表已经证明能改善学习动机。

## 世界规律与简化

- 格子排列、原料份数、产量与建筑连接是游戏约定，不模拟现实承重。公共设施周围留出空间。
- 木球在坡道上受重力影响，平地减速，角色走过去接触可以推动，停下后还能再推。点球后用右侧“收起球”取回，可重复使用。最多四个，满额提示先收起，不再 13 秒自动消失；位置和速度随世界保存，离线不滚动。球道仍是简化模型，不是完整刚体、材料弹性或结构受力模拟。
- 浅溪中涉水，桥上正常行走。地图南侧 `(0, 11)` 有带入口木坡道的深水泳池；入水自动浮起、划水和踢腿，键盘/摇杆控制方向，游向池沿或点“上岸”离开。暂停时移动和划水停止，重载可继续。若池体预定区域已有玩家建筑，不生成泳池，不覆盖旧作品；原溪流地形、存档 key 和版本均未改变。动作与浮起为游戏简化，没有溺水惩罚，也不是现实游泳教学。
- 制砖依次展示调湿成形、干燥、烧制和冷却，总计约24秒。黏土与树枝可正常采集；不合适的工艺通过免费试样观察裂纹。现实说明默认折叠，温度和时间不是所有砖窑通用的参数。
- 豆苗在合适水分下累计生长约90秒；缺水或积水会暂停生长。排水好的园地会排出积水，也可以移栽。现实生长时间经过快进；首版固定适宜光照，没有完整生态模拟。
- 顶部季节按钮显示本地日期、季节、天气和钟点。春 3–5 月、夏 6–8 月、秋 9–11 月、冬 12–2 月。天气按当天日期固定（晴、多云、小雨、雷雨、有风、下雪、有雾），同一天一致，不联网查预报。天空、草地、雾和雨雪落叶跟着季节与天气变化。蒲公英只在春夏按日照/半阴/占地推进花序，夜间花序合拢，秋天留叶，冬天休眠。菜豆园仍固定适宜环境，不因季节阻断，不表示现实冬季露地也能这样种。窑和植物仍只在页面可见且未暂停时推进。树木成长、草地个体年龄和自然传播尚未实现。
- 卡通钟面有 1–12 数字、短时针和长分针，跟这台设备的本地时间走。06:00–18:00 为白天、18:00–20:00 为傍晚、20:00–06:00 为夜间，不按纬度计算日出日落。
- 页面隐藏、退出或主动暂停后，加工与植物不会计算离线时间；查看窑炉或菜园时仍会推进。家长负责计时，孩子可随时停下。

帮助页有可选的 AI 建筑点子卡。它们是预先制作的示意建议，可改动和试验；当前没有儿童实时 AI 聊天。

球交互检查：启动开发服务后运行 `node test/ball-check.js`，覆盖推动、停止再推、坡道、暂停、取回、真实触屏选球和刷新恢复。存档保持原 v1 key，新增可选 `toys` 字段；旧存档缺省为无场景球，不改旧库存与建筑。

游泳检查：`node test/swim-check.js`，覆盖电脑、平板与手机的浅水/桥面/坡道/泳姿/浮起/减速/暂停/出岸/水中保存与旧建筑兼容，以及真实键盘、触屏摇杆和“上岸”按钮。

生命检查：`node test/life-check.js`，覆盖手机/平板观察面板同步、暂停/模拟隐藏、刷新、季节/夜景、增量模型及升级前备份下载原文。[规则、来源与边界](docs/生命系统数据与简化.md)说明当前两物种模型，不是完整生态。

时钟、扩图发现与工坊检查：`node test/expansion-craft-check.js`，覆盖电脑/手机钟面、扩图、三类发现领取与重载、新区建造/滚球、图卡、鼠标/真实 Chromium 触屏拖放与取消。截图保存在系统临时目录。第 6 项的[未知物品与自行车链路设计](docs/未知物品与自行车链路设计.md)已交付，当前没有可骑自行车。

位置开垦检查：`node test/land-position-check.js`，独立电脑/手机/平板上下文覆盖真实方向键/触屏摇杆到边界、疑问引导/高亮、取消/离开/重入、就近面板、提交瞬间重验、暂停/搭建隐藏与新区重载。截图为系统临时目录 `valley-land-boundary-*`。核心规则也由 `test/land-position.test.js` 覆盖。

实体工坊检查：`node test/workshop-check.js`，独立电脑/手机/平板上下文覆盖实体投料、移槽/拿回、短拉/有效拉杆、多结果、取消/多指/隐藏/关闭、二维备用、大桌空心箱及存档。手机镜头单独适配，材料/拉杆扩大命中区域。试摆会话见 `src/workshop-session.js`，正式制作仍只调用 `GameState.craft()`；不新增存档字段。验收与真实试玩边界见[实体工坊里程碑](docs/三维实体工坊里程碑.md)。

轮轴试装：在河谷中找到“轮轴试装”目标。点轮子或按“装上”连接到对应插槽；拖动已安装的轮子可转动，也可用“一小格”按钮；再次点轮子或按“取下”拆开。读数显示左右轮与固定轴角度，可验证两轮互不带动。试验架是机构演示件，不扣材料、不保存为作品，也不模拟承重、传动或骑行。运行 `npm test` 与 `npm run test:axle` 检查轮轴规则及电脑/平板交互。

去日谷：走到小溪下游的渡口，点“去日谷”。坐船的路程在游戏里变短了。日谷里随时可以点“回家”。也可以先到南边热气球草场起飞，在空中点“看风景去日谷”；那段路程和天气是简化的。中途刷新会回到出发的草坪，不会停在半空。日谷可以采楮皮、竹子，在纸坊做和纸，再折纸鹤、纸船、纸鲤鱼旗或纸拉门。纸鹤用一张和纸，纸船用两张并排，这样每种格子只有一个结果；真实折纸通常一张纸、很多步。和纸的蒸煮、敲打、抄纸和晾干被缩短到大约 20 秒。答题只在角色菜单里，排在“看一看 / 做手工”后面，只给少量楮皮或贴纸，不做也能采集、做纸、盖章和回家。印章本可以打开看看。暂停菜单里的年龄档只是对话默认长短，不记录生日。

去外星谷：只能坐热气球。渡口没有这一项。起飞后进入游览，点“飞向星星（外星谷）”。旁边写着：这是游戏里的幻想航线，真实的热气球飞不出大气层。星空过场大约三秒半，可以跳过；暂停或隐藏页面就停住。中途刷新回到出发草坪，不留在半空。外星谷里重力大约是地球的三分之一，跳得更高，规律还是同一个，这是简化模型，不是完整的行星物理。可以取盐、看陨石、看光苔和跳跳球兽。盐加清水，放得多会析出盐晶，放得少几乎没有；大约 20 秒，暂停、隐藏或离线都不往前走。光苔是幻想生物，可以装进游戏里直接提供的玻璃罩，展柜能摆在河谷，不能种进菜园，也不能放养。小咕、晶晶博士和零一是预写角色，没有实时对话。符号谜题可以跳过，提示和答案都在；学会的符号会写在路牌上。10–12 岁有四进制题，外星的 10 等于我们的 4。印章和纪念品都有不答题的做法。外星谷里可以点“回家”，也可以坐热气球飞回来。天上有一颗蓝色的小点，表示家的方向，这是游戏里的想象。

旅行流程检查：`node test/travel-check.js`。它使用独立浏览器上下文。桌面、平板和手机视口的自动点击不能代替孩子或真实平板试玩。范围和不能宣称的内容见 [旅行框架与日谷里程碑](docs/旅行框架与日谷里程碑.md)。

去美谷：渡口上“去日谷”下面还有“去美谷”。坐的是更大的船，过场大约 3 秒，可以跳过，文案写明路程在游戏里变短了。美谷里随时可以点“回家”。热气球升空后可以点“看风景去美谷”；那段路程和天气是简化的。中途刷新会回到出发的草坪。美谷可以采枫树汁、原木、旧布头、纸、南瓜和树枝，不用答题。枫糖用 10 份树汁加树枝熬成 1 份，大约 20 秒；现实里含糖大约 2% 的树汁要多得多。图书馆的纸和日谷的和纸不是同一种。轮轴用三根木棍叠起来，因为两根并排已经是篱笆，这是游戏约定。项目板按画、做、试、改走，纸飞机距离和风车转速来自固定表，不是空气动力学。拼布、南瓜灯和感谢卡全年都能做。南瓜灯只有笑脸、猫脸和星星。交换板只在 10–12 岁出现：3 份豆子换 1 份枫糖浆，不是货币。答题排在“看一看 / 做手工”后面，只给少量枫树汁或贴纸。

美谷流程检查：`node test/mei-check.js`。它使用独立浏览器上下文。自动视口不能代替孩子或真实平板试玩。范围见 [美谷里程碑](docs/美谷里程碑.md)。

## 存档

自动存档保存在**当前浏览器、当前网站地址**的本地存储里，不会自动在电脑与平板间同步。不同端口、换浏览器、清理网站数据或隐私窗口都可能导致无法看到同一份存档。

暂停菜单 → 给大人：备份与导入存档，可以下载 JSON，也可以导入备份。导入需要确认；无效存档不替换当前世界。损坏的原始本地存档会先保留原文备份，备份失败时不会覆盖原文。浏览器不能保存时，页面会提示导出。

旧 v1 世界缺少 `clock`/`flora` 时自动补充初始生命字段，原库存、建筑和园地保留。第一次写入新字段前先保存并读回确认原文到 `yuanyuan-river-valley-v1-before-life`；已有不同备份时使用数字后缀，不覆盖已有备份。暂停菜单大人区域可以下载升级前 JSON；备份失败则不覆盖旧主存档。

扩图字段 `land` 保存种子、已开区块与发现领取 ID；旧世界缺省无新区、无已领发现。加载缺少扩图/领取字段的本地旧世界，首次覆盖前使用 `yuanyuan-river-valley-v1-before-expansion` 原文备份，已有不同备份采用数字后缀；同时缺生命字段时优先用扩图备份保留整份原文。主 key 与 v1 不变，暂停菜单统一显示“下载升级前的备份”。

旅行使用可选字段 `travel`，年龄档使用可选字段 `settings.ageBand`（`little` / `bigger` / `older` / 空）。主存档键仍是 `yuanyuan-river-valley-v1`，版本仍是 1。家里的建筑、背包、窑和菜园留在原来的字段；外谷方块只写在 `travel.realms`。第一次写入旅行字段前，把当时的原文写到 `yuanyuan-river-valley-v1-before-travel` 并读回核对；已有不同内容时用数字后缀。备份写失败就不覆盖主存档。暂停菜单里“下载升级前的备份”仍下载生命/扩图那份原文；旁边另一枚按钮的说明是“下载旅行升级前的备份”，下载的是旅行升级前的原文。

导入时如果 `travel` 不合法，整份文件拒绝，当前世界不动。本机读取时如果只有日谷位置出界，人回到日谷码头，家里的建筑和背包不动；如果外谷数据本身不合法，回到河谷的安全位置，并在暂停菜单的大人区域提示。家里的数据如果也坏了，仍按原来的损坏存档保护处理，不改用旅行修复。

新物品 id 包括 `kozo`、`bamboo`、`bamboo-strip`、`washi`、`paper-crane`、`paper-boat`、`paper-koinobori`、`paper-door`。还没有这些 id 的旧版本会拒绝带它们的存档。升级前可以先下载旅行备份。不要为了兼容去改主存档键或版本号。

外星谷写在 `travel.realms.xing`，美谷写在 `travel.realms.mei`。版本仍是 1。两份升级前备份用不同的键，不会互相覆盖。

第一次覆盖一份还没有 `travel.realms.xing` 的存档之前，把当时的原文写到 `yuanyuan-river-valley-v1-before-xing`，读回再比；已有不同备份时用数字后缀。备份失败就不写主存档。新游戏没有旧原文，不写这份备份。暂停菜单里“下载外星谷升级前的备份”下载的就是这份原文。本机读取时，外星谷位置出界就回到那里的热气球草坪；外星谷记录本身不合法就回河谷，家里的建筑和背包不动。导入的文件如果外星谷不合法，或者家里的建筑、菜园里有幻想且活着的物种，整份拒绝。

又增加的物品 id：`salt`、`salt-crystal`、`meteorite`、`glowmoss`、`glowmoss-case`、`glass-dome`、`glyph-plaque`。不认识这些 id 的旧版本会拒绝带它们的存档。升级前可以先下载外星谷备份。

美谷写在已有的 `travel.realms.mei` 里：玩家、方块、箱子、标记、枫糖加工、项目卡、交换记录和南瓜灯表情。主存档键和版本仍是 `yuanyuan-river-valley-v1` / 1，`travel.schema` 仍是 1。第一次把一份还没有 `realms.mei` 的原文写成带美谷的存档之前，把当时的原文写到 `yuanyuan-river-valley-v1-before-mei` 并读回核对；已有不同内容时用数字后缀。备份写失败就不覆盖主存档。已经带空美谷的新世界不再写这份备份。暂停菜单里“下载美谷升级前的备份”下载的是这份原文。导入时美谷字段不合法会拒绝整份文件。本机读取时，只有美谷位置出界就回到美谷港口；美谷数据本身不合法就回到河谷，家里的建筑、背包、日谷和外星谷里仍然合法的部分不动。

美谷新物品 id：`maple-sap`、`maple-syrup`、`log`、`log-wall`、`cloth`、`quilt-patch`、`quilt`、`paper`、`axle`、`paper-plane`、`windmill-mini`、`pumpkin`、`pumpkin-lantern`、`thanks-card`。不认识这些 id 的旧前端会拒绝带它们的存档。

远眺使用可选字段 `travel.discovered`（`ri` / `mei` / `xing`）和 `travel.keepsakes`。主存档键和版本仍是 `yuanyuan-river-valley-v1` / 1。旧存档没有这些字段时，会按 `travel.visited`、当前所在的谷，以及 `travel.realms` 里已经留下的建筑、加工或离开码头的位置，把去过的谷视为已发现。空的美谷、外星谷记录不会因此被当成发现。第一次把这份原文写成带远眺字段的存档之前，写到 `yuanyuan-river-valley-v1-before-vista` 并读回核对；已有不同内容时用数字后缀。备份写失败就不覆盖主存档，也不覆盖已有的 `before-mei` 和 `before-xing`。新游戏没有旧原文，不写这份备份。暂停菜单里“下载远眺升级前的备份”下载的是这份原文。发现不是出发门槛：渡口和热气球按钮照样能用。漂流瓶纪念只记在 `travel.keepsakes`，不进材料表，不限时，不扣东西。

## 检查与开发

```sh
npm test
npm run build
# 首次运行浏览器检查需要安装 Chromium：
npx playwright install chromium
# 保持上面的 preview 进程运行，在另一终端执行：
npm run test:browser
```

浏览器检查默认使用 `http://127.0.0.1:5174`，可通过 `GAME_TEST_URL` 指定其他测试地址。它使用独立浏览器上下文，不清理正常使用者的存档。检查记录写入 `output/browser-verification.json`。

GitHub Pages 预览由 `.github/workflows/preview.yml` 在旅行分支每次 push 时执行 `npm ci && npm run build`，`VITE_BASE=/3dplay/`，再发布到 `gh-pages`。地址是 https://mmlingyu.github.io/3dplay/ 。不设置 `VITE_BASE` 时，构建仍用相对路径，原来的 `/play/` 部署不变。预览没有后端时，游戏只用浏览器里的存档和仓库里的日谷角色，不弹连接失败。若 Pages 还没打开，这个地址会是 404。本机可以看同一份预览构建：

```sh
VITE_BASE=/3dplay/ npm run build
VITE_BASE=/3dplay/ npm run preview
```

然后打开 http://127.0.0.1:4173/3dplay/ 。冒烟检查是 `PREVIEW_URL=http://127.0.0.1:4173/3dplay/ node test/preview-smoke.js`。

核心逻辑在 `src/game-state.js`；配方与材料在 `src/game-data.js`；三维世界在 `src/world.js`；面板在 `src/panels.js`；操作与时钟在 `src/main.js`。模型、纹理和图标均为本项目用代码制作的原创资产。
