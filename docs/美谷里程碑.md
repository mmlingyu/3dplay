# 美谷里程碑

日期：2026-10-20。这是叠在日谷旅行框架上的美谷 MVP。旅行框架来自分支 `cursor/travel-ri-mvp-76ec`，本轮复用，没有重写。河谷仍是中性的家，不标国家。外星谷仍只有 id。

这些是脚本和 Chromium 视口里的自动检查，不是孩子试玩，也不是真实平板或 Safari。

## 做了什么

- 渡口在“去日谷”下面增加“去美谷”。过场大约 3 秒，可以跳过。文案是“路程在游戏里变短了”。美谷用的是更长的大船，和河谷小船不是同一个模型。
- 热气球升空后可以点“看风景去美谷”。文案写明路程和天气在游戏里被简化。航行中刷新回到出发草坪，落地在美谷草坪。
- `REALMS.mei.playable` 为真时才显示这两条路。外星谷的占位没有改。
- 美谷地图：原木小屋（转角咬合）、红谷仓、廊桥、抽水风车、国家公园一角（步道、守护员小屋、间歇泉）、小镇图书馆、枫树林、原木堆、南瓜地、旧衣回收箱、纸架、树枝堆、枫糖小屋、自行车铺（有轮子，没有旗）、项目板、纸飞机来信。访客小院可以摆。朋友的家和园子是红色预览，原因是“这里是朋友的家和园子，去访客小院搭建吧。”
- 抽水风车的叶片一直在转：有风时更快（每秒约 1.8 弧度），没风时慢（每秒约 0.15 弧度）。间歇泉的说明是“不是地质模拟”。
- 五个人：Maya、Will、Orv、Rivera、Joe。Orv 的说明里有“以真实历史人物为原型的游戏角色”。Joe 带着桶。衣服是日常的，没有帽子和旗。
- 项目板目标是风车、纸飞机、原木小屋。步骤是画、做、试、改。说明写明这是游戏里的简化模型。没有失败分，没有倒计时。改可以不做，也可以再来一次。完成盖章 `mei-project`，并给一次纪念品（小风车、纸飞机摆件或原木墙）。
- 纸飞机距离表是 `[[4,8,5],[7,14,9],[5,9,6]]`，中间机头加中间机翼是 14。风车转速表是 `[[1,2,1],[2,4,3],[2,5,3]]`；没有风也没有风箱时不转；有动力时再加上风的 2 和风箱的 2。原木小屋看屋顶有没有把围好的范围盖上。
- 年龄：不设置时按小朋友，三步，改的按钮是“再试一次”和“完成”。7–9 岁是四步，并排对比。10–12 岁有材料上限（风车 6、纸飞机 4、原木小屋 8）和两列结果。项目卡在 `travel.realms.mei.projects`，最多 20 张。7–9 和 10–12 改的时候必须只改一个部分。改不扣材料。做风车时会把叶片接到轮轴试装上再转一小格；不装叶片时，轮轴快照和原来一样。
- 枫糖 10 份树汁加 1 根树枝熬成 1 份，五步、大约 20 秒。说明写明现实里要多得多。看面板时继续走；暂停、页面隐藏或不调用 tick 时不走。枫树林全年都能采，不用答题。早春（3 月、4 月）多一句“这时候树汁多”。
- 原木两根做成原木墙。旧布头按年龄拼成拼布块，四块拼布块做成挂毯。纸加木棍是纸飞机。木板加轮轴是小风车。轮轴是三根木棍叠起来：两根并排已经是篱笆，格子的材料袋必须唯一，所以轴多用一根。这是游戏约定。图书馆的纸和日谷的和纸不是同一种。小风车可以摆回河谷，只有有风的日子才转。
- 英语在 `src/mei-tutors.js`，全部 `review.status: draft`。小朋友是 hello、sun、tree、friend、build。7–9 岁有 c-a-t 和 build、measure、test、fix。10–12 岁有 “It didn't work. Let's change one thing.” 录音 id 只有占位，没有音频文件，启动时不播放。
- 知识包：`knowledge/valleys/mei.json` 记 id 和出处；角色正文在 `src/mei-tutors.js`。未发布的 `draft-hidden` 不出现。接口失败时用本地包。`?valley=mei` 才读美谷；未知的谷不再回落到日谷。在美谷答对给 2 份枫树汁和贴纸 `mei-quiz-…`，不给印章。日谷答对仍是楮皮和 `ri-quiz-`。
- 印章五枚，都不靠答题：`mei-arrive`、`mei-syrup-first`、`mei-quilt-first`、`mei-windmill-spin`、`mei-project`。印章本把日谷和美谷合在一起。还没盖到的美谷章不会写成“已经盖上”。
- 纸飞机来信可以“先放着”，记在 `travel.story.seen`。10–12 岁才看得到交换：3 份豆子换 1 份枫糖浆，不是货币。4–9 岁和不设置看不到交换按钮，可以送礼。
- 南瓜灯（南瓜加木棍，表情只有笑脸、猫脸、星星）和感谢卡（纸加拼布块）全年都能做，不看日期。南瓜不种回河谷菜园。

## 存档

主存档键 `yuanyuan-river-valley-v1`，版本 1，`travel.schema` 仍是 1。

美谷只写在 `travel.realms.mei`：玩家、方块、箱子、标记、加工、项目卡、交换记录、南瓜灯表情。家里的建筑、背包和日谷留在原来的位置。

第一次覆盖一份还没有 `realms.mei` 的存档之前，把当时的原文写到 `yuanyuan-river-valley-v1-before-mei`，读回再比。顺序是旅行备份、美谷备份、生命/扩图备份、损坏备份，然后才写主存档。任何一步备份失败都不写主存档。已有不同备份时用数字后缀。新世界一开始就有空的美谷，不再写这份备份。暂停菜单可以下载“美谷升级前的备份”。

导入的文件如果美谷字段不合法，整份拒绝。本机读取时：只有位置出界就留在美谷、回到港口；美谷数据不合法就回河谷，家里和日谷不动。刷新时如果当前是美谷，会重新打开美谷。熬到一半的枫糖按存档里的已用时间恢复，不补离线时间。

新物品 id 会让旧前端拒绝新存档。名单在 README 的存档一节。客户端导入上限仍是 500 万字符。
