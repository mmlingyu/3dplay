# 日谷后端改动需求

日期：2026-10-20。本文只记录 IdeaLab 后端需要的接口和存档兼容。本仓库是 3dplay 游戏前端，不包含 FastAPI、`knowledge_tutors.py` 或 `valley_store.py`。前端在接口不可用时使用仓库内的 `src/ri-tutors.js`，日谷仍可游玩。

## 知识接口

### 不带参数的旧接口必须保持原样

`GET /api/knowledge/tutors` 不带查询参数时，响应必须与旧客户端的快照一致：只包含河谷（`valley` 缺失或为 `he`）的角色。不要把日谷角色混进这份响应。旧的诗词、数学、词语题目和“诗必须用诗泉”的约束继续只作用于河谷。

前端还会再滤一次：无参数结果里 `valley` 不是 `he` 或缺省的角色不会进入河谷对话；`published === false` 或 `review.published === false` 的角色不显示。

### 按谷读取

`GET /api/knowledge/tutors?valley=ri` 返回日谷角色包。失败、空列表或过滤后没有角色时，前端改用本地日谷包，不阻断渡船、采集、造纸、折纸或回家。

可选：`GET /api/knowledge/valleys` 列出谷 id、显示名和是否可玩。本版前端不依赖它。`mei`（美谷）和 `xing`（外星谷）只保留 id，没有内容。

### 建议的角色字段

日谷内容不要写进现有的河谷 `valley-tutors.json`。单独存放，并带这些字段：

- `valley`：`ri`。河谷角色继续是 `he` 或缺省。
- `subjects`：至少 `lang-ja`（日语）和 `craft`（手工）。
- 年龄档：`little`（4–6）、`bigger`（7–9）。`older`（10–12）可以没有；前端会按 older → bigger → little 回退。
- 选项可带 `icon`、`audio`、`reading`。读音放在 reading 字段，不把假名和简体中文写成同一个字。
- `ref`：知识句需要出处。当前本地稿使用的是和纸工艺、合掌造、平假名的公开条目。
- `review.status`：日文在母语者审阅前保持 `draft`。
- `published: false` 的角色不要下发。向导角色可以只有说明、没有题目。
- 题目不是门槛。答对只表示可选的少量原料或贴纸，由前端发放；接口不要把题目做成地图、配方或时长的开关。

管理端的知识列表需要能按 `valley` 筛选。本仓库没有管理界面，这一项留在后端。

## 存档

`valley_store` 必须接受带可选 `travel` 和 `settings.ageBand` 的 v1 存档，也必须继续接受没有这两个字段的旧存档。不要因为多了 `travel` 拒绝整份快照，也不要因为没有 `travel` 清空河谷的建筑、背包、园地或窑炉。

前端约定：

- 主 key 仍是 `yuanyuan-river-valley-v1`，`version` 仍是 `1`。
- `travel` 只放外谷。河谷的方块、箱子、玩家和玩具留在根字段。
- 第一次把没有 `travel` 的原文写成带 `travel` 的存档之前，前端把**原始字符串**写入 `yuanyuan-river-valley-v1-before-travel`。已有不同备份时用数字后缀。备份写不回去就不覆盖主 key。
- 导入整份文件时，不合法的 `travel` 会拒绝整个文件。本地加载则保留原文备份，坏掉的外谷记录退回河谷，家里的建筑和背包不动。若家里的数据本身也损坏，沿用原有的损坏备份和抢救规则，不改走旅行备份。
- 新物品 id（`kozo`、`bamboo`、`bamboo-strip`、`washi`、`paper-crane`、`paper-boat`、`paper-koinobori`、`paper-door`）会让不认识这些 id 的旧前端拒绝新存档。服务端不要把这种存档改写成旧前端读不懂的另一套版本号。

客户端导入上限是 500 万字符，文件选择约 2 MiB。外谷方块上限 600。旅行字段会增大同一份 JSON，存储配额需要按这个上限留余量，而不是按“只有河谷方块”估算。

## 本版前端已经做的降级

- 日谷角色、题目、读音和出处在 `src/ri-tutors.js`。
- 日语和说明短句放在 `public/audio/ri/`。文件播不出来时，前端改用 `speechSynthesis`。日文仍是草稿，待母语者审阅，不要把本地稿当成已审定课文。

## 2026-10-21 日谷街区字段

主 key 和 `version: 1` 不变。日谷 `travel.realms.ri` 可以多两个可选字段，旧档没有它们也必须能读：

- `storyShard`：只有 `true` 才保留。缺省或 `false` 表示还没拿到潮之片。
- `city`：可选。`lanterns`、`shops`、`trainLoops` 是整数；`queue`、`signal`、`shoes`、`thanks` 是可选布尔。不认识的键整段拒绝，不要静默改掉家里的建筑。

第一次把没有这两个字段的原文写成带 `storyShard: true` 或 `city` 对象的存档之前，前端把当时读到的原始字符串写入 `yuanyuan-river-valley-v1-before-ri3`。已有不同备份时用数字后缀。只是进入日谷、还没写入这些字段时，不另做这份备份。
